## 五、关键操作流程

### 5.1 流程 A：批量导入 → AI 生成候选（对应 V1）

```
[反馈列表] 点击「批量导入」
    ↓
上传 CSV / 粘贴文本，预览解析结果
    ↓
确认导入 → feedback 批量写入，status = NEW
    ↓
[AI 候选工作台] 点击「生成候选问题」
    ↓
选择范围（模块 / 时间 / 状态=NEW）
    ↓
后端：按模块硬分组 → 组内 AI 语义聚类
    ↓
写入 ai_candidate_issue（DRAFT）+ feedback_issue_link
    ↓
写入 ai_generation_log（SUCCESS）
    ↓
页面展示候选卡片列表
```

### 5.2 流程 B：PM 确认 → 生成正式问题（对应 V1、V4、V5）

```
[候选卡片详情] 查看 AI 理由 + 展开 7 条原文
    ↓
├─ 确认 → status = CONFIRMED → 生成 issue
├─ 修改后确认 → 编辑标题/描述 → status = MODIFIED → 生成 issue
├─ 合并到… → 选择已有 issue → status = MERGED
└─ 驳回 → 填写 handle_remark（必填）→ status = REJECTED
                                      → 关联 feedback 回到 NEW
    ↓
issue 生成后，点击「生成需求草稿」
    ↓
AI 输出 → 存入 issue.ai_draft_content
    ↓
PM 编辑 → 保存为 issue.final_content
    ↓
点击「建立改进任务」→ 手选 P0/P1/P2 + 填写 priority_reason
    ↓
improvement_task 创建，status = TODO
```

### 5.3 流程 C：DEV 推进与验证（对应 V6）

```
[任务看板] 点击「开始开发」→ TODO → IN_PROGRESS
    ↓
点击「提交验证」→ IN_PROGRESS → PENDING_VERIFY
    ↓
├─ 验证通过 → PENDING_VERIFY → DONE
└─ 验证不通过 → PENDING_VERIFY → IN_PROGRESS（remark 必填）
    ↓
每次变更写入 task_event（含操作人角色快照）
```

## 六、六态反馈设计（课程硬性要求）

每个列表页和每个操作都必须覆盖以下六种状态：

| 状态 | 触发场景 | 页面表现 |
| --- | --- | --- |
| **加载中** | 请求发起 | 表格骨架屏（Naive UI `n-skeleton`） |
| **空数据** | 查询无结果 | 居中插图 + 「暂无数据」+ 引导操作按钮 |
| **成功** | 操作完成 | 轻提示（message）+ 数据刷新 |
| **失败** | 网络错误 / 5xx | 内联错误条 + 「重试」按钮 |
| **冲突** | 他人已修改同一记录 | 对话框提示「数据已被修改，请刷新后重试」 |
| **无权限** | 越权操作 | 按钮**隐藏或置灰** + 若直接调接口返回 403 提示 |

### 页面级权限处理原则

> **不是"点了报错"，而是"不该看到的就看不到"。**

- CS 账号登录后，菜单中**不显示**「候选问题」「改进任务」
- DEV 账号在任务详情页**看不到**优先级编辑控件
- 若绕过前端直接调接口，后端 `@PreAuthorize` 拦截返回 403

| 路由 | 组件 | 允许角色 | 守卫 |
| --- | --- | --- | --- |
| `/login` | LoginView | 全部 | 已登录跳转首页 |

| `/candidates` | CandidateWorkbench | PM | 角色守卫 |
| `/candidates/:id` | CandidateDetailView | PM | 角色守卫 |
| `/issues` | IssueListView | PM, DEV | 角色守卫 |
| `/issues/:id` | IssueDetailView | PM, DEV | 角色守卫 |
| `/tasks` | TaskBoardView | PM, DEV | 角色守卫 |
| `/tasks/:id` | TaskDetailView | PM, DEV | 角色守卫 + 归属校验 |

**守卫逻辑**：
```javascript
// 全局前置守卫：检查登录状态与角色权限
router.beforeEach((to, from, next) => {
  const token = getToken()
  if (!token && to.path !== '/login') return next('/login')
  if (to.meta.roles && !to.meta.roles.includes(userStore.role)) {
    return next('/403')   // 无权限页面
  }
  next()
})
```

## 八、AI 候选工作台的三种特殊状态展示

这是挑战赛道的演示重点：

| 情况 | 页面表现 | 数据来源 |
| --- | --- | --- |
| **AI 有依据** | 卡片显示置信度 + 关联原文 + AI 理由 | `ai_generation_log.status = SUCCESS` |
| **依据不足** | 卡片显示「⚠ 信息不足，建议人工补充」标签，不臆造内容 | AI 返回 `INSUFFICIENT_EVIDENCE` |
| **模型失败** | 顶部横幅：「AI 服务暂不可用，已切换为手工模式」，下方显示手工创建入口 | `ai_generation_log.status = FAILED/TIMEOUT` |

**「查看 AI 原始输出」入口**：每张卡片和每次生成都可点击查看：
- 当时的 Prompt 输入快照
- AI 返回的原始文本（未加工）
- 模型名称、耗时、成功/失败状态
